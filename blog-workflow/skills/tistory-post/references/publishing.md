# 현재 브라우저 발행 절차

티스토리의 구 Open API는 종료되었다. 과거 스킬의 비공개 엔드포인트나 CodeMirror 상태 조작을 발행 방법으로 복사하지 않는다. 현재 제공된 브라우저 도구 문서를 읽고 화면에 보이는 편집기를 조작한다.

1. 요청된 대상과 작업을 확인한다. 신규/기존 글 수정, 비공개/공개/예약을 구분한다. 이미 사용자가 정한 범위에서 계속 진행하며 매번 재승인을 요구하지 않는다. 모호한 외부 변경이 있으면 파일·미리보기·검수 결과를 먼저 완성한다.
2. 공개 글 수정이면 원본 본문과 실제 URL을 먼저 보관한다. 기존 임시저장 복구 팝업이 있으면 사용자 작업을 덮어쓰거나 삭제하지 않는다. 새 글을 만들기 전 이력과 관리 목록으로 중복을 확인한다.
3. 현재 에디터의 모드를 확인한다. 제목과 본문은 분리해 정상 입력/붙여넣기를 사용한다. JavaScript로 에디터 내부 값을 바꿔 저장됐다고 판단하지 않는다.
4. 로컬 이미지 파일을 지원되는 파일 선택/업로드 도구로 넣고, 반환된 이미지 위치와 표시를 확인한다. 파일 업로드가 막히면 실제 오류와 원고 패키지를 남기고 종료하며 불명확한 대체 엔드포인트를 추측하지 않는다.
5. 카테고리·태그·공개 범위·예약 일시를 저장 화면에서 확인한다. 검수한 버전이 맞는지 확인한 후 요청된 저장을 수행한다.
6. 관리 목록 또는 저장된 글을 다시 열어 제목·대표 문장·이미지·공개 범위를 확인한다. 클릭 직후의 메시지만으로 성공을 확정하지 않는다. 실제 글 주소를 복사한다.
7. 공개 글이면 `verify-public`과 브라우저 시각 검수를 수행하고 `record-publication`으로 기록한다. 비공개면 공개 검증 대신 재열기 관측으로 `draft`를 기록한다.

로그인 만료·권한·CAPTCHA 등은 실제로 마주친 상태만 보고한다. 발행 결과가 불명확하면 `publication_unknown`으로 기록하고 목록에서 확인하기 전에는 재발행하지 않는다. 태그 상한·수식 지원·네이티브 팝업은 과거 경험을 영구 사실로 간주하지 말고 현재 UI에서 확인한다.

## 실증한 주의점 (2026-09-13)

- 숫자 범위 두 곳의 단일 물결표가 티스토리 미리보기에서 취소선으로 해석되었다. 숫자 범위는 “4개부터 10개까지”처럼 쓰고 실제 렌더링을 확인한다. 원고 검사기는 이 위험을 경고한다.
- 네이티브 이미지 업로드와 대표 이미지 지정은 서로 다른 조작이었다. 저장 폼의 대표 이미지를 별도로 확인한다. 기본 업로드가 alt를 보존한다고 가정하지 않는다.
- 코드 블록은 줄바꿈과 들여쓰기를 포함한 textContent를 원고와 대조한다. 스킨의 숨겨진 관련 글 표를 본문 표 개수에 포함하지 않는다.
- 이번 비공개 글은 관리 목록의 비공개 표시와 실제 글의 수정 링크 /manage/post/175를 확인했다. 이 번호를 후속 글에 재사용하지 않는다.
