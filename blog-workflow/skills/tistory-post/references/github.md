# 완성한 TIL의 GitHub 반영

현재 프로젝트의 `blog-workflow/config.json`에 `git_sync.enabled: true`가 설정되어 있다. 사용자가 TIL 정리 뒤 GitHub 반영까지 연결하도록 요청했다. 사용자 요청으로 완성한 TIL은 이 절차까지 진행하되 현재 요청이 초안·로컬 전용이면 그 범위를 따른다. 이 설정은 다른 저장소 공개나 티스토리 공개 발행의 권한을 만들지 않는다.

## 실행

저장소 루트에서 실행한다. 실제로 이번 작업에서 완성한 파일명을 전달하고, 글의 기술적 사실과 공개 가능한 범위는 먼저 검수한다.

```bash
python3 blog-workflow/skills/tistory-post/scripts/github_sync.py plan \
  --config blog-workflow/config.json --files '실제로 완성한 노트.md'

python3 blog-workflow/skills/tistory-post/scripts/github_sync.py sync \
  --config blog-workflow/config.json --files '실제로 완성한 노트.md' \
  --message '이번에 정리한 주제를 설명하는 커밋 메시지'
```

`plan`에서 선택 파일, 변경 파일, 대상 저장소·브랜치·현재 커밋을 확인한다. `sync`는 현재 내용을 다시 검사한다. 루트 `.md`와 그 노트가 참조하는 `img/`, `images/`의 그림만 받는다. 그림도 `--files`에 명시한다. 새로운 폴더 구조가 필요하면 사용자의 요청에 맞춰 범위를 먼저 확장한다. 삭제는 자동 반영하지 않는다.

별도 임시 인덱스로 정상 Git 커밋을 만들어 다른 파일의 스테이징 상태를 보존한다. 저장소의 커밋 훅과 서명 설정은 유지한다. 선택한 파일에 사용자가 이미 스테이징한 변경이 있으면 그 중간 상태를 덮어쓰지 않도록 멈춘다. 폴더 전체를 대상으로 `git add .`를 수행하지 않는다.

## 결과와 실패

- `no_changes`: 원격과 로컬 커밋이 일치하고 선택 파일에 변경이 없다. 빈 커밋이나 푸시를 만들지 않는다.
- `synced`: 커밋 이후 원격 브랜치가 그 커밋을 가리키는지 확인했다. 반환된 `commit`으로 해당 저장소의 커밋 링크를 보고한다.
- 원격 접근 실패, 다른 브랜치·URL, 기존 미푸시 커밋, 원격 변경, 미완료 병합은 사유를 보고한다. 자동 강제 푸시나 사용자 변경 덮어쓰기를 하지 않는다.

커밋은 만들어졌지만 푸시가 확인되지 않았다면 다음 명령으로 같은 커밋을 재사용한다.

```bash
python3 blog-workflow/skills/tistory-post/scripts/github_sync.py retry \
  --config blog-workflow/config.json
```

재시도는 기록한 커밋의 부모·파일 범위·내용·대상을 다시 확인한다. 원격에 이미 반영되어 있으면 새 커밋 없이 완료로 확인한다. 응답이 끊기거나 실패했을 때 같은 글의 커밋을 반복 생성하지 않는다. 커밋 생성 직후 프로세스가 종료되어 재시도 기록 자체가 없으면, 앞선 로컬 커밋을 먼저 조사한다.

진행 중 상태와 성공 이력은 Git 내부 디렉터리의 `til-sync/`에 남긴다. 이 디렉터리는 공개 GitHub 파일에 포함되지 않는다. 두 프로세스가 동시에 같은 동기화를 진행하지 않도록 잠근다. 이는 사용자 또는 외부 프로그램의 동시 Git 조작 전체를 잠그는 기능은 아니다.

## 실행 시점

이 연결은 Codex가 TIL 정리를 마칠 때 실행한다. 스킬 설치만으로 파일 저장 감시나 정기 실행을 시작하지 않는다. 나중에 예약 실행을 구성하면 같은 명령을 마지막 단계로 호출하면 된다. GitHub 푸시는 티스토리의 비공개 저장·공개 발행과 별도의 상태로 관리한다.
