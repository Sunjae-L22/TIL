# 운영과 측정

첫 단계는 카탈로그, 검증 가능한 글 패키지, 실제 발행 이력이다. Search Console·애드센스 연결과 정기 운영은 그 다음 단계다. 연결 상태와 마지막 성공 수집 시각을 따로 보관한다.

## 실제 지표 연결 후

Search Console의 검색어/페이지별 노출·클릭·CTR, 방문 분석의 참여·재방문, AdSense의 수익·RPM을 각자의 출처와 기간으로 구분한다. 데이터가 없으면 `not_connected` 또는 `not_collected`로 표시한다. 서로 다른 기간·집계 단위의 숫자를 합치지 않는다. 검색 클릭을 광고 클릭으로 해석하지 않는다.

제목 변경 후보는 충분한 노출과 낮은 CTR 등을 근거로 추린다. 순위만으로 성과를 평가하지 않고 비교 기간과 변경일을 남긴다. 새 글은 실제 수요와 독자 문제, 기존 글 보강은 빠진 설명과 오래된 사실을 기준으로 제안한다. 수익과 함께 API·도구 비용을 기록한다. 애드센스 승인/수익은 보장하지 않는다.

## 예약 실행을 요청받았을 때

Codex 자동화 도구로 사용자가 정한 빈도·범위·발행 모드를 저장한다. 로컬 자료 접근에는 컴퓨터와 앱 실행이 필요하다. 자동화 상태 ACTIVE와 각 필수 데이터 소스 연결을 따로 확인한다. 마지막 성공 이후 새로 생긴 자료만 처리하며 콘텐츠 해시와 발행 이력으로 중복을 막는다.

예약 초안 문구 예: “새 자료를 확인하고 기존 카탈로그와 대조한다. 새 기여가 있는 자료를 검증 가능한 원고와 이미지로 준비한다. 설정된 발행 권한을 따른다. 새 자료·성공·실패·사용자 조치가 있을 때만 알리고 변화가 없으면 조용히 종료한다.”

이 문구는 제안 템플릿이며 실제 예약 작업이 생성된 것이 아니다. 주기와 외부 발행 범위가 정해지지 않았다면 이를 임의로 활성화하지 않는다.
